# SQL 문법 정리

## 없어진 기록 찾기

### 사용한 SQL

```sql
SELECT ou.ANIMAL_ID, ou.NAME
FROM ANIMAL_INS AS ins
RIGHT OUTER JOIN ANIMAL_OUTS AS ou
    ON ins.ANIMAL_ID = ou.ANIMAL_ID
WHERE ins.ANIMAL_ID IS NULL
ORDER BY ou.ANIMAL_ID;
```

### 문제 이해하기

이 문제는 입양을 간 동물 중에서 보호소에 들어온 기록이 없는 동물을 찾는 문제이다.

사용하는 테이블은 두 개이다.

| 테이블 | 의미 |
| --- | --- |
| `ANIMAL_INS` | 동물이 보호소에 들어온 기록 |
| `ANIMAL_OUTS` | 동물이 입양을 간 기록 |

정상적인 데이터라면 입양 기록이 있는 동물은 보호소에 들어온 기록도 있어야 한다.

하지만 이 문제에서는 `ANIMAL_OUTS`에는 존재하지만 `ANIMAL_INS`에는 존재하지 않는 동물을 찾아야 한다.

즉, 기준은 `ANIMAL_OUTS`이다.

### 핵심 아이디어

`ANIMAL_OUTS` 테이블에 있는 모든 입양 기록을 기준으로 가져온 뒤, `ANIMAL_INS`와 연결해 본다.

연결했을 때 `ANIMAL_INS` 쪽 값이 `NULL`이라면, 입양 기록은 있지만 보호소 입소 기록은 없는 동물이라는 뜻이다.

```sql
WHERE ins.ANIMAL_ID IS NULL
```

이 조건이 바로 없어진 기록을 찾는 핵심이다.

### 핵심 문법

#### 1. SELECT

```sql
SELECT ou.ANIMAL_ID, ou.NAME
```

문제에서 출력해야 하는 값은 동물의 아이디와 이름이다.

입양 기록이 기준이므로 `ANIMAL_OUTS` 테이블의 별칭인 `ou`를 사용해서 출력한다.

```sql
ou.ANIMAL_ID
ou.NAME
```

#### 2. FROM

```sql
FROM ANIMAL_INS AS ins
```

`FROM`은 조회를 시작할 테이블을 정한다.

여기서는 `ANIMAL_INS` 테이블에 `ins`라는 별칭을 붙였다.

별칭을 사용하면 이후에 컬럼을 더 짧고 명확하게 작성할 수 있다.

```sql
ins.ANIMAL_ID
ou.ANIMAL_ID
```

#### 3. RIGHT OUTER JOIN

```sql
RIGHT OUTER JOIN ANIMAL_OUTS AS ou
    ON ins.ANIMAL_ID = ou.ANIMAL_ID
```

`RIGHT OUTER JOIN`은 오른쪽 테이블의 데이터를 모두 남기는 조인이다.

여기서 오른쪽 테이블은 `ANIMAL_OUTS AS ou`이다.

따라서 `ANIMAL_OUTS`에 있는 입양 기록은 모두 유지되고, `ANIMAL_INS`와 매칭되는 데이터가 있으면 함께 붙는다.

매칭되는 데이터가 없으면 `ANIMAL_INS` 쪽 컬럼은 `NULL`이 된다.

### ON의 역할

```sql
ON ins.ANIMAL_ID = ou.ANIMAL_ID
```

`ON`은 두 테이블을 어떤 기준으로 연결할지 정한다.

이 문제에서는 두 테이블 모두 동물을 구분하는 컬럼으로 `ANIMAL_ID`를 가지고 있다.

그래서 `ANIMAL_INS`의 `ANIMAL_ID`와 `ANIMAL_OUTS`의 `ANIMAL_ID`가 같은 행끼리 연결한다.

### WHERE로 없는 기록 찾기

```sql
WHERE ins.ANIMAL_ID IS NULL
```

`RIGHT OUTER JOIN`을 하면 `ANIMAL_OUTS`의 데이터는 모두 남는다.

그런데 `ANIMAL_INS`에 같은 `ANIMAL_ID`가 없는 경우에는 `ins.ANIMAL_ID`가 `NULL`이 된다.

따라서 `ins.ANIMAL_ID IS NULL` 조건을 걸면 보호소 입소 기록 없이 입양 기록만 있는 동물을 찾을 수 있다.

### ORDER BY

```sql
ORDER BY ou.ANIMAL_ID;
```

`ORDER BY`는 조회 결과를 정렬할 때 사용한다.

문제에서 동물의 아이디 순으로 정렬하라고 했으므로 `ou.ANIMAL_ID`를 기준으로 정렬한다.

오름차순은 기본값이기 때문에 `ASC`는 생략할 수 있다.

### 실행 흐름

1. `ANIMAL_INS` 테이블을 기준으로 조회를 시작한다.
2. `RIGHT OUTER JOIN`으로 `ANIMAL_OUTS` 테이블의 데이터를 모두 남긴다.
3. `ANIMAL_ID`가 같은 데이터끼리 연결한다.
4. 연결되지 않은 데이터는 `ANIMAL_INS` 쪽 컬럼이 `NULL`이 된다.
5. `ins.ANIMAL_ID IS NULL`인 행만 남긴다.
6. `ou.ANIMAL_ID`, `ou.NAME`을 출력한다.
7. 결과를 `ou.ANIMAL_ID` 기준으로 오름차순 정렬한다.

### LEFT JOIN으로 바꿔 쓰기

이 문제는 `LEFT JOIN`으로도 풀 수 있다.

입양 기록인 `ANIMAL_OUTS`를 왼쪽에 두고, 입소 기록인 `ANIMAL_INS`를 오른쪽에 붙이면 된다.

```sql
SELECT ou.ANIMAL_ID, ou.NAME
FROM ANIMAL_OUTS AS ou
LEFT JOIN ANIMAL_INS AS ins
    ON ou.ANIMAL_ID = ins.ANIMAL_ID
WHERE ins.ANIMAL_ID IS NULL
ORDER BY ou.ANIMAL_ID;
```

이 방식은 기준 테이블인 `ANIMAL_OUTS`를 먼저 쓰기 때문에 문제 의도가 더 직관적으로 보인다.

### 최종 정리

이 문제의 핵심은 `ANIMAL_OUTS`에는 있지만 `ANIMAL_INS`에는 없는 데이터를 찾는 것이다.

`OUTER JOIN`을 사용해서 입양 기록을 모두 남긴 뒤, 입소 기록과 연결되지 않은 행을 `IS NULL`로 찾으면 된다.

```sql
SELECT ou.ANIMAL_ID, ou.NAME
FROM ANIMAL_INS AS ins
RIGHT OUTER JOIN ANIMAL_OUTS AS ou
    ON ins.ANIMAL_ID = ou.ANIMAL_ID
WHERE ins.ANIMAL_ID IS NULL
ORDER BY ou.ANIMAL_ID;
```
