# SQL 문법 정리

## 조건에 맞는 도서 리스트 출력하기

### 사용한 SQL

```sql
SELECT BOOK_ID, DATE_FORMAT(PUBLISHED_DATE, '%Y-%m-%d') AS PUBLISHED_DATE
FROM BOOK
WHERE CATEGORY = '인문'
    AND PUBLISHED_DATE BETWEEN '2021-01-01' AND '2021-12-31'
ORDER BY PUBLISHED_DATE;
```

## JOIN에서 ON과 USING의 차이

`ON`과 `USING`은 둘 다 `JOIN`할 때 두 테이블을 어떤 기준으로 연결할지 정하는 문법입니다.

가장 큰 차이는 **조인 조건을 얼마나 직접적으로 쓰느냐**와 **결과에 조인 기준 컬럼이 어떻게 표시되느냐**입니다.

### 1. ON

```sql
SELECT *
FROM BOOK B
JOIN AUTHOR A
    ON B.AUTHOR_ID = A.AUTHOR_ID;
```

`ON`은 두 테이블의 컬럼을 직접 비교해서 조인 조건을 작성합니다.

```sql
ON B.AUTHOR_ID = A.AUTHOR_ID
```

이처럼 `테이블명.컬럼명 = 테이블명.컬럼명` 형태로 조건을 명확하게 적습니다.

`ON`은 컬럼명이 서로 달라도 사용할 수 있습니다.

```sql
SELECT *
FROM BOOK B
JOIN AUTHOR A
    ON B.WRITER_ID = A.AUTHOR_ID;
```

위 예시처럼 `BOOK` 테이블에서는 `WRITER_ID`, `AUTHOR` 테이블에서는 `AUTHOR_ID`라는 서로 다른 이름의 컬럼을 기준으로 조인할 수 있습니다.

또한 조인 조건을 여러 개 쓰거나, 추가 조건을 함께 작성하기 쉽습니다.

```sql
SELECT *
FROM BOOK B
JOIN AUTHOR A
    ON B.AUTHOR_ID = A.AUTHOR_ID
    AND B.CATEGORY = '인문';
```

정리하면 `ON`은 더 일반적이고, 조건을 자유롭게 작성할 수 있는 방식입니다.

### 2. USING

```sql
SELECT *
FROM BOOK
JOIN AUTHOR
    USING (AUTHOR_ID);
```

`USING`은 두 테이블에 **같은 이름의 컬럼**이 있을 때 사용할 수 있습니다.

```sql
USING (AUTHOR_ID)
```

이 문장은 아래 `ON` 조건과 같은 의미입니다.

```sql
ON BOOK.AUTHOR_ID = AUTHOR.AUTHOR_ID
```

즉, `BOOK` 테이블에도 `AUTHOR_ID`가 있고, `AUTHOR` 테이블에도 `AUTHOR_ID`가 있을 때 `USING (AUTHOR_ID)`로 간단하게 작성할 수 있습니다.

하지만 컬럼명이 다르면 `USING`은 사용할 수 없습니다.

```sql
-- 사용할 수 없음
FROM BOOK
JOIN AUTHOR
    USING (WRITER_ID);
```

만약 `AUTHOR` 테이블에 `WRITER_ID`라는 컬럼이 없다면 위 문법은 맞지 않습니다.

### 3. 결과 컬럼 차이

`ON`과 `USING`은 `SELECT *`를 했을 때 결과 컬럼에도 차이가 있습니다.

#### ON을 사용한 경우

```sql
SELECT *
FROM BOOK B
JOIN AUTHOR A
    ON B.AUTHOR_ID = A.AUTHOR_ID;
```

`ON`을 사용하면 조인 기준이 된 컬럼이 양쪽 테이블에서 각각 출력될 수 있습니다.

예를 들어 `BOOK.AUTHOR_ID`와 `AUTHOR.AUTHOR_ID`가 둘 다 결과에 나올 수 있습니다.

#### USING을 사용한 경우

```sql
SELECT *
FROM BOOK
JOIN AUTHOR
    USING (AUTHOR_ID);
```

`USING`을 사용하면 조인 기준 컬럼인 `AUTHOR_ID`가 결과에서 하나로 합쳐져 출력됩니다.

따라서 `SELECT *` 결과를 볼 때는 `USING`이 더 깔끔하게 보일 수 있습니다.

### 4. 언제 ON을 쓰고 언제 USING을 쓸까?

#### ON을 쓰는 경우

- 두 테이블의 조인 컬럼 이름이 다를 때
- 조인 조건을 명확하게 보이고 싶을 때
- 조인 조건이 여러 개이거나 복잡할 때
- 실무나 문제 풀이에서 안전하게 작성하고 싶을 때

```sql
SELECT B.BOOK_ID, A.AUTHOR_NAME
FROM BOOK B
JOIN AUTHOR A
    ON B.AUTHOR_ID = A.AUTHOR_ID;
```

#### USING을 쓰는 경우

- 두 테이블의 조인 컬럼 이름이 같을 때
- 조인 조건을 짧게 쓰고 싶을 때
- `SELECT *` 결과에서 중복 컬럼을 줄이고 싶을 때

```sql
SELECT BOOK_ID, AUTHOR_NAME
FROM BOOK
JOIN AUTHOR
    USING (AUTHOR_ID);
```

### 5. 핵심 정리

| 구분 | ON | USING |
| --- | --- | --- |
| 사용 조건 | 컬럼명이 달라도 가능 | 두 테이블의 컬럼명이 같아야 함 |
| 작성 방식 | `ON A.ID = B.ID` | `USING (ID)` |
| 조건 표현 | 자유롭게 작성 가능 | 같은 이름의 컬럼 기준으로 간단히 작성 |
| `SELECT *` 결과 | 조인 기준 컬럼이 중복 출력될 수 있음 | 조인 기준 컬럼이 하나로 합쳐짐 |
| 추천 상황 | 대부분의 경우, 복잡한 조인 | 단순하고 컬럼명이 같은 조인 |

### 최종 정리

`ON`은 조인 조건을 직접 작성하는 방식이고, `USING`은 같은 이름의 컬럼을 기준으로 조인할 때 간단히 쓰는 방식입니다.

문제 풀이에서는 `ON`을 사용하면 조건이 더 명확하게 보이기 때문에 가장 안전합니다.

반면 두 테이블에 같은 이름의 컬럼이 있고, 단순한 조인이라면 `USING`을 사용해서 SQL을 더 짧게 작성할 수 있습니다.

### 문제 이해하기

이 문제는 도서 정보를 담고 있는 `BOOK` 테이블에서 2021년에 출판된 `인문` 카테고리의 도서를 조회하는 문제입니다.

조회해야 하는 컬럼은 도서 ID인 `BOOK_ID`와 출판일인 `PUBLISHED_DATE`입니다.

조건은 두 가지입니다.

1. `CATEGORY`가 `'인문'`이어야 합니다.
2. `PUBLISHED_DATE`가 2021년 1월 1일부터 2021년 12월 31일 사이여야 합니다.

또한 결과는 `PUBLISHED_DATE`를 기준으로 오름차순 정렬해야 합니다.

### 핵심 문법

#### 1. SELECT

```sql
SELECT BOOK_ID, DATE_FORMAT(PUBLISHED_DATE, '%Y-%m-%d') AS PUBLISHED_DATE
```

`SELECT`는 조회할 컬럼을 선택할 때 사용합니다.

이 문제에서는 `BOOK_ID`와 `PUBLISHED_DATE`를 출력해야 합니다.

`PUBLISHED_DATE`는 날짜 형식을 `YYYY-MM-DD` 형태로 맞춰 출력해야 하므로 `DATE_FORMAT()` 함수를 사용합니다.

#### 2. DATE_FORMAT()

```sql
DATE_FORMAT(PUBLISHED_DATE, '%Y-%m-%d')
```

`DATE_FORMAT()`은 날짜 데이터를 원하는 형식의 문자열로 변환할 때 사용하는 함수입니다.

`%Y`는 4자리 연도, `%m`은 2자리 월, `%d`는 2자리 일을 의미합니다.

따라서 `DATE_FORMAT(PUBLISHED_DATE, '%Y-%m-%d')`는 날짜를 `2021-01-01`과 같은 형태로 출력합니다.

#### 3. FROM

```sql
FROM BOOK
```

`FROM`은 데이터를 조회할 테이블을 지정할 때 사용합니다.

도서 정보는 `BOOK` 테이블에 들어 있으므로 `FROM BOOK`을 작성합니다.

#### 4. WHERE

```sql
WHERE CATEGORY = '인문'
    AND PUBLISHED_DATE BETWEEN '2021-01-01' AND '2021-12-31'
```

`WHERE`은 원하는 조건에 맞는 행만 조회할 때 사용합니다.

이 문제에서는 카테고리가 `인문`이고, 출판일이 2021년인 도서만 필요합니다.

두 조건을 모두 만족해야 하므로 `AND`로 연결합니다.

#### 5. BETWEEN

```sql
PUBLISHED_DATE BETWEEN '2021-01-01' AND '2021-12-31'
```

`BETWEEN A AND B`는 값이 A 이상 B 이하인 데이터를 찾을 때 사용합니다.

여기서는 `PUBLISHED_DATE`가 2021년 1월 1일부터 2021년 12월 31일까지인 도서를 조회합니다.

#### 6. ORDER BY

```sql
ORDER BY PUBLISHED_DATE;
```

`ORDER BY`는 조회 결과를 정렬할 때 사용합니다.

문제에서 출판일을 기준으로 오름차순 정렬하라고 했으므로 `ORDER BY PUBLISHED_DATE`를 작성합니다.

오름차순은 기본 정렬 방식이기 때문에 `ASC`를 생략할 수 있습니다.

### 실행 흐름

1. `BOOK` 테이블에서 데이터를 조회합니다.
2. `CATEGORY`가 `'인문'`인 도서만 남깁니다.
3. `PUBLISHED_DATE`가 2021년인 도서만 남깁니다.
4. `BOOK_ID`와 형식을 맞춘 `PUBLISHED_DATE`를 출력합니다.
5. 결과를 `PUBLISHED_DATE` 기준으로 오름차순 정렬합니다.

### 최종 정리

이 문제의 핵심은 `WHERE`로 카테고리와 출판일 조건을 걸고, `DATE_FORMAT()`으로 날짜 출력 형식을 맞춘 뒤 `ORDER BY`로 정렬하는 것입니다.

```sql
SELECT BOOK_ID, DATE_FORMAT(PUBLISHED_DATE, '%Y-%m-%d') AS PUBLISHED_DATE
FROM BOOK
WHERE CATEGORY = '인문'
    AND PUBLISHED_DATE BETWEEN '2021-01-01' AND '2021-12-31'
ORDER BY PUBLISHED_DATE;
```
